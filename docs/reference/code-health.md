# 代码治理与固定验收

修改巡检、问题分组、候选、验证或检查点时阅读。任务参数的实际默认值由公开配置接口与类型定义提供。

## 职责与冻结边界

遵循[四层运行时基线](../../specs/runtime-four-layer-definition/spec.md)。治理位于消息链之外，
Console 调用 Harness 的公开入口；Harness 管任务、源码清单、候选写入边界、验证和交付。
源码修改不会改变当前进程加载的宿主，也不会改变本次运行的权限；新实现完成 PR 交付并由 GitHub 合入后才能供后续任务使用。原有 Case 与机器人任务修复权限不随治理扩大。

新任务冻结最新远端 main 提交及其源码，不包含操作者未提交改动；交付与清理遵循
[Harness PR 交付契约](delivery.md)。
公开 `.env.example`、`env.example`、`*.env.example` 纳入源码；真实 `.env`、`.env.*`、
`local.env` 等环境文件继续排除。私有环境目录中的文件不会因示例文件名获得公开资格。
原工作区、暂存区、Git 元数据、凭据和线上数据不开放给修复 Agent 写入。

候选可以修改选定范围的产品、快照、Harness 和检查器实现。既有 Python/前端测试、规格、
黄金原则、忽略规则、构建和检查配置保持固定；架构检查的声明式规则也不能改变。
涉及业务规则、权限政策、标准调整或缺失外部事实的发现保留为待判断。

宿主持有初始清单和独立的 Git 忽略规则副本，比较候选时不执行候选的源码选择或权限代码。
新增忽略文件、测试及私有配置在忽略过滤之前拒绝；候选不能通过修改忽略规则藏匿改动。
补丁、检查点和回滚也由宿主基于该清单完成。验证使用私有临时 Git 索引，不改操作者索引。

## 源码快照与 Git 查询

巡检的 `source` 是不含 `.git` 的纯源码快照，不执行 Git 检查，也不以 Git 可用作为读取
契约和源码的前提。新任务冻结远端 main 的基准提交和快照摘要，original_branch 记录目标 main；
`source.repository_context` 向模型明确提供目录类型、冻结事实、当前检查点摘要及可查询的
候选工作区路径。旧记录缺失的原始分支保持未知，不依据当前仓库补造历史信息。

准备、编码和审核通过 `git -C <候选工作区>` 只读查询；草案目录和 `baseline_root` 均不是 Git 仓库。
宿主解析真实 git-dir/common-dir，在外层 bubblewrap 和 Codex 原生权限中只读开放，
不开放原工作区或 Git 写权限。继续设置 `GIT_OPTIONAL_LOCKS=0`，不注入进程级
`GIT_DIR`、`GIT_WORK_TREE` 或其他检查的 `GIT_INDEX_FILE`。`git diff HEAD` 展示本任务相对冻结基线的候选；累计补丁仍以宿主相对初始远端快照导出为准。

模型启动前，通过相同两层沙箱校验候选 Git 目录和基准提交；失败以 `coding_environment`
终止并保留已验收检查点，不进入产品修复重试或待判断计数。纯快照跳过这项 Git 检查。
宿主的 `rg` 可执行文件单独只读投影至固定工具目录，外层与模型命令共用 PATH；
未安装时提示使用 grep/find，不阻断任务。当前运行任务和历史日志不随本次代码更新改写。
Console 的 dev 依赖包含 full 检查与 sdist 重建所需的 pip，WSL 基础工具包含 ripgrep。
worker 保持 `UMask=0077`；模拟不安全权限的测试显式设置目标权限，不依赖调用者 umask。
仓库检查记录 pytest 的 `SUBFAILED` 子测试失败，不能因输出前缀不同遗漏失败节点。

SQLite 辅助文件可在并发提交时被删除。宿主仅对 journal/WAL/SHM 接受已删除 inode 的
零链接元数据，仍校验普通文件、当前属主和私有权限；主数据库及其他私有文件继续要求
单链接。该处理不重新执行事务体，也不忽略 I/O、身份替换或仍存在的不安全文件。

## 固定验收与候选实现

验证准备、编码、独立审核分别调用 Codex。准备和审核只读候选；编码不能修改既有测试或
已冻结的新测试。宿主进程不从候选加载 Harness。验证工具运行于无网络的独立子进程：

- 固定的仓库检查入口、检查脚本与组件审核代码负责判定；架构、公开边界、编码及制品检查
  显式读取候选路径，候选将同名检查器改成始终成功不能替换本次判定入口。
- 测试视图保留候选实现，覆盖为固定测试和配置。固定 pytest 驱动先加载真正的测试框架，
  再导入候选源码，避免候选同名 `pytest` 模块替代测试驱动。
- 快照、Harness 和检查器的修改需要冻结回归依据；没有回归依据的临时越界修改不能验收。
  新回归测试由宿主验证哈希后加入交付，修复 Agent 不能自行加入或重写验收测试。

已有 lint/结构检查能直接证明的问题复用机械检查。语义问题及关键基础设施修改先自动创建
回归草案、执行、分类并独立审核，再冻结草案开始编码。行为缺陷要求原候选失败、修复后通过；
行为保持重构要求原候选和修复候选都通过，并给出原结构与改进的可复核依据。
草案环境错误、缺失执行结果、跳过和无法证明的预期不能冒充产品缺陷。

基线和候选使用相同的 fast/full 范围。跨域、Console、工程脚本或架构修改使用 full。
已有确定性问题按结构化发现比较，已有测试失败按 node id 比较；目标必须消失，新增问题、
未知失败和缺失证据仍阻断。pytest 另记录实际测试身份集合摘要与跳过项，执行集合变化或新增跳过
不能仅靠退出码为零通过验收。既有失败单独记录，保留失败结果，不把候选接受写成全部检查通过。

## 巡检批次与问题组

从初始统一源码清单生成有限领域批次。`all` 包含运行时、Console 实现、工程脚本、普通文档
及公开环境示例；标准和测试供只读上下文使用。文件按内容分段，单批为 64 KiB 级输入，
给既有 128 KiB 证据边界留下上下文空间；记录路径、行段、偏移、文件摘要、块摘要与输入文件。
只有执行适配器确认实际投递了本批全部源码块且模型返回有效结果，批次才完成。
二进制输入标为未覆盖，工具失败与未投递输入不能计为完成。

按领域逐批巡检，然后按根因和相关调用方处理该领域发现的问题。相同根因使用稳定分组标识，
相关路径和组间依赖单独记录。待判断问题不阻断独立组；依赖未通过组的问题暂缓。
全部计划批次完成才能显示「完成本轮范围巡检」，只证明计划输入已处理，不保证找出了全部缺陷。

治理版本 6 沿用独立 CodeHealthOptions 和 PR 自动交付，增加文档扫描与修改范围分离。旧快照不套用新的文档规则，旧记录保持只读。新请求必须提供 budget：
`{mode: fixed_groups, count: N}`、`{mode: discovered_groups, count: N}` 或
`{mode: time, seconds: N}`，三者互斥且数值为正整数。
默认按验收通过的问题组数停止，count=1；切换时间模式时默认 7200 秒。
主表单直接展示全部治理参数，推理强度默认 xhigh（极高），单个问题最多尝试默认 3 次。
数量模式不设任务或单次模型/验证执行的时间上限；底层调用传递 timeout=None，继续监督
心跳和主动取消。时间模式仅使用单调时钟计算任务总时限，不设修复成功数量上限或额外
单次执行时限。连接、Git 环境预检及进程清理仍使用各自技术超时，不作为修复预算。
任务总时限到期报告 budget_exhausted。无时间预算时，底层意外报告超时属于 execution_timeout，
不是预算耗尽；技术异常不计入产品重试。终态清理活动批次、组和尝试。
新建请求移除 step_timeout_seconds；旧任务按冻结版本运行、保留历史，不迁移旧参数。
取消和技术故障均保留已持久化检查点，错误摘要显示阶段、限制及证据入口。

accepted_groups 仅统计已通过独立审核且检查点事务成功的问题组；原 fixed 仍统计发现条数。
一个根因组解决多条发现仍计一组，失败、待判断和重试不增加成功计数。第 N 个检查点保存后
以 fixed / fix_limit_reached 结束，不再启动后续工作。有限批次耗尽而数量未达时，按实际
发现和覆盖结束，不重复巡检凑数。页面分别展示数量目标、已用时间与范围覆盖。
同一错误和相同候选内容重复出现时结束本组；错误、候选摘要和尝试证据保留，继续其他独立组。
任务内尝试编号唯一，另外记录所属组和组内次数。

## 按发现数量收敛修复目标

新增“按发现问题数”，按首次发现顺序统计去重后的根因组，默认输入 1，保持原有默认模式。
初始机械扫描或任一审计批次返回后，发现组数达到 N 就停止后续审计，不等待领域剩余批次。
只将最先发现的 N 组冻结到 selected_group_ids 并执行修复；同一批多出的发现和原始检查
证据仍完整保留，但不纳入本轮修复。discovered_groups、selected_groups 与 accepted_groups
分别表示实际发现、选中和验收通过的组数，不能因批次返回超额而截断实际发现计数。

此模式不设时间预算。选中问题沿用固定验证、独立审查、单个问题最多尝试及无进展停止。
选中组内的依赖按可执行顺序处理；未选中的依赖不自动加入目标。修复失败、待判断或依赖
未就绪时记录真实结果并结束，不再寻找替代问题。没有达到 N 但有限范围已结束时，修复
已发现的所有组并报告发现不足。发现阈值是停止巡检的条件，不能在开始修复前直接终止任务。

达到阈值后的正常收尾记录 discovery_limit_reached；成功、部分成功、失败和待判断由
实际验收结果区分，覆盖仍可为 partial。取消和技术异常保持自己的停止原因。为验证目标
进行的读源和固定仓库检查仍执行，不把它们当作继续扩展发现目标。

## 说明类轻量验收

documentation 类发现中的普通 Markdown、Python 普通注释与模块包说明可先生成轻量候选。
固定宿主核对实际差异：Python 去除模块 docstring 后 AST 与代码 token 必须相同，编码、
类型检查、lint 等指令不得改变；函数和类 docstring、CLI/工具消费的模块说明走标准流程。
标准、提示词、配置、检查器、权限和关键基础设施不进入轻量路径。
轻量候选进行差异、语法/lint、公开边界和 Markdown 本地链接检查，并独立审核说明与源码
及契约的一致性，记录 documentation_only 证据，不新增行为测试或重复两轮 fast。
实际差异超范围时恢复组前检查点，记录路由原因，再建立标准回归依据；路由重选不消耗
产品修复尝试。独立审核仍可拒绝候选，未验收内容不能进入检查点。

每组通过固定验证与独立审核后保存不可变检查点，并计算相对于初始远端源码的累计补丁。
后续组失败只回滚到最近检查点。取消、预算耗尽、执行异常时恢复并交付已经验收的检查点；
未验收内容不进入累计交付。检查点或补丁摘要不一致时拒绝下载。新任务由受信宿主交付正式 PR 并等待 squash 自动合并，不部署。

## 私有数据库与维护锁

Harness 的创建/恢复共享锁和维护独占锁使用根目录中永久保留的 `harness.lock`，
不能使用 SQLite 数据库本体或辅助文件作为文件锁载体。锁文件要求当前属主、0600、
单链接、非符号链接，并核对打开描述符与路径的 inode；冲突仍非阻塞返回。

Harness 与 EvaluationResultStore 共用 PrivateDatabase。构造过程由各库的
`<数据库名>.init.lock` 串行保护，等待上限 5 秒。只有不存在的库以排他创建方式打开并关闭
原始描述符，且在任何构造者交给 SQLite 前关闭。已有版本 1 的库仅通过 SQLite 读取版本，
不再次直接打开/关闭数据库文件，不重复建表或写版本；版本 0 的结构初始化在事务内完成。
保留版本、表结构、DELETE 日志模式、同步强度和主库/辅助文件安全检查。

宿主存储异常记录逻辑库名、操作阶段、SQLite 扩展码/名称及调用栈，不记录参数或任务正文。
回滚/关闭的二次错误不得覆盖原异常，业务事务体不自动重放。任务以 `storage_error` 阻断，
未结束的尝试标为 `interrupted`，不计入产品修复次数；已有记录不重新判定。
独立审查通过的尝试与检查点元数据在同一数据库事务提交，之后才推进内存检查点。
提交成功但关闭异常时重新读取已持久化检查点，再恢复候选，避免丢弃已验收成果。
数据库持续不可写时记录终态保存失败并结束 worker；恢复可读写后由现有 worker 存活检查
将遗留活动任务及尝试标为中断，原始存储详情保留在 worker 日志。

涉及存储或 worker 协议更新时，在维护锁内确认 Harness 与 Evaluation 空闲，并通过 SQLite
备份 API 保存一致性副本。常规运行使用当前独立锁协议，不保留旧双锁切换流程。

任务是否可运行由当前宿主的 `PIPELINE_VERSION` 和 `GOVERNANCE_VERSION` 分别判断，定义见
[models.py](../../src/chatcopilot/harness/models.py)。不匹配的冻结 worker 不直接恢复；Case/机器人
任务按接续入口创建新 worker，治理任务创建新快照，原补丁、日志和失败结论保持只读。
SQLite 的 `user_version` 是独立的数据库结构版本，不能与任务流程或治理版本混用。

## API、历史与页面

保留 `POST /api/harness/code-health/tasks`、配置、历史、详情、进度、取消及组内补丁接口。
新来源使用 `governance_version=6`；`governance` 记录 coverage/groups/checkpoints，attempt
增加 version/group_id/group_attempt。详情与分页摘要显示发现、已修复、待判断和未处理数量。
新增 `GET /api/harness/tasks/{id}/candidate-patch` 读取最近已验收的累计补丁。
`check-log` 只允许读取本任务已登记的检查日志。任务 payload 增加轻量摘要，分页不传大清单。

详情显示当前组、验证依据、组内补丁、失败原因、领域批次及实际文件块摘要。
「未发现问题」「发现但待判断」「已修复部分」「范围巡检完成」分别表达发现与覆盖结果；
取消、超时及工具失败仍保留自己的执行状态。已有检查点在取消后仍可下载。

旧记录只读，不迁移快照、不重跑或重新判定结果。旧候选当前可用性返回未知，显示历史验收，
不使用新源码规则重新计算旧候选有效性。数量从已有发现和 resolved_ids 投影，
未记录的覆盖显示未知。例如历史记录发现一项但因旧保护范围被搁置，应显示发现 1、
待判断 1、已修复 0；不能由旧的 not_reproduced 状态推断没有问题。重新启动创建新快照。
