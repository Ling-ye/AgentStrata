# Harness 修复与交付

Harness 是消息链外的独立 worker，接受测评 Case 实例和机器人任务的结构化证据。
使用方式见 [操作指南](../guides/harness.md)，架构见[多 Agent 修复规格](../../specs/harness-multi-agent/spec.md)。

## 来源与黄金原则

原始观测、人工反馈和验收预期分别冻结。测评只允许补充修复提示，不能覆盖原答案；
机器人允许可选修复提示与预期，两项为空时沿原请求和契约调查，不制造标准答案。
缺失、截断或过期证据保留缺口；Evaluation 继续拥有原测评和评分。
[黄金原则索引](harness-principles.md)及其引用随任务冻结，不受候选修改影响。

## 按需角色协作

Main 安排首轮与处理根因变化、分歧；Plan 追踪调用链并提出最小方案；Coding 只写产品；
Test 只写独立测试草案；Review 只读审查。所有角色共用运行器，使用独立会话与权限。
角色不得自行创建嵌套委派。正常阶段由宿主推进，明确代码或测试错误只返工相关角色。
Plan 用 proceed/blocked 区分待验证假设与必要条件缺失。Coding/Test 的局部工具说明放 notes，
gaps 只记录绑定实际验收目标的缺口；检查通过不能直接抹去明确的证据或外部交付缺口。
根因假设来自 Plan，验证器只产出验证定义与执行结果。无进展按实际通过的检查项比较，
目标内部分检查改善仍可继续下一轮。

现成 Case 直接复用，允许先形成候选后补验证。正式验收在独立冻结快照运行相同测试；
原始目标、保护集与独立审核全部满足才可 fixed。评分、环境和材料错误不是产品失败；
参考答案不进入被测 Agent 输入。图片输入物化、后端传图和输出交付分别验证。
真实模型、模拟外部回执与真实 QQ 交付分别记录。

默认三轮、累计 3600 秒，所有角色返工共用预算；恢复不重置。连续两轮没有新增有效
证据时停止。局部候选保留为待审阅，不进入自动交付。会话外部接受未知时先对账。

## 修复流程记录

问题、原则、计划和角色输出以不可变 JSON 保存，任务数据库保留可搜索身份和引用。
摘要和阅读索引按角色提供，大正文按需读取，不嵌套复制整个历史。Console 展示角色、
输入、结论和证据；命令日志独立分页。查询不推进任务或探测 worker。

## 隔离与交付

每任务冻结远端 main，创建独立 worktree、分支、依赖环境与临时目录。宿主使用 uv 和
冻结依赖声明准备环境，所有角色只读依赖；Coding 是产品唯一写入者，Test 只写草案。
正在执行的宿主、既有测试、评分、权限和黄金原则固定；候选 Harness 代码不能接管本次验收。

宿主生成绑定精确候选、目标和验证记录的 AcceptedCandidate，再按[交付契约](delivery.md)
提交、普通推送、创建正式 PR、等待必要检查与审查、squash 合入远端 main。主干前进需复验。
修复、发布、合并和清理分别记录，不自动部署、不更新操作者本地 main。

### 控制与生命周期

`HarnessController` 保留公开操作与查询。`control_types` 定义 worker 存活三态及调度结果，
`control_service` 通过端口统一取消、恢复、接续与失联核对；`worker_runtime` 持有装配时的配置快照，
负责 systemd、冻结目录和进程事实。存活判断检查任务的执行锁、修复与交付 unit，以及尚未完成的
systemd job。调度结果 unknown 不等于进程停止，未知时保留取消请求与任务占用。

修复和交付 worker 共用 `worker_execution`，按维护共享锁、任务控制锁、执行锁的顺序登记。
worker 等待控制锁，在锁内复读执行资格；只有另一个实际执行者持有执行锁时才按重复 worker 退出。
登记后释放控制锁，执行结束才释放执行锁和维护锁，因此探测不会导致待启动 worker 误退出。
取消只在 worker 自行收尾或宿主确认停止后完成；测评取消的请求回执不等于外部测评已经结束。
失败或未结束时保留关联供重试。
状态写入使用事务条件保护，迟到的 worker 不得把取消状态恢复成运行或成功。

`current_evaluation_id` 只记录修复阶段测评，`delivery_evaluation` 只记录交付复测，二者不双写。
交付复测中取消保留修复已有终态；交付流程确认执行结束才清除自己的引用，执行期间异常也保留引用。
显式取消能处理 blocked 交付，取消未完成时保留请求与 cancel_pending，定时器继续核对。
任一测评引用存在时保留任务占用、禁止清理，交付复测未收尾也禁止恢复或接续修复。

`get/list/progress` 不探测进程或推进生命周期。Console 启动时装配控制入口；初始化失败仅使 Harness
入口不可用，不影响其他页面。现有每分钟定时入口先核对活动任务，再处理交付；单项失败不阻止其他任务。
CLI 的 `reconcile` 可主动核对，取消、恢复和接续也会立即检查运行事实。定时器不可用时不能承诺
失联状态的自动更新时限。完整设计见 [Harness 控制生命周期](../../specs/harness-control-lifecycle/spec.md)。

六层静态门禁目前只覆盖控制 Types/Service 及直接 CLI/Console 入口，包含函数内导入与重导出检查；
其他 Harness 模块仍按领域基线逐步整理。静态检查不是 Python 执行沙箱，也不能证明运行时状态正确。

## 协议切换

新协议为 pipeline 9。旧记录阻止创建新任务；维护切换需确认 worker、外部测评和 PR
均已结束，保存一致性数据库备份与工作区恢复材料后清空活动索引。旧任务目录和证据
保留原位，归档清单记录恢复位置；不迁移旧任务、不续跑旧 worker。
