# 在本机创建、运行和改进 Agent 应用

先按项目所在的位置打开工作台。

- **已有 Linux/WSL2 源码部署**　启动原发行版并在本机浏览器打开 `http://localhost:8910`。首次准备 Console 或检查服务时，使用[实例运维指南](instances.md#运维控制台)。
- **Windows 11 x64 安装版**　打开「AgentStrata 开发工作台」安装包，从开始菜单启动并点击「准备并打开开发工作台」。向导使用 Ubuntu 24.04 / WSL2 的独立用户，准备好后自动打开带本机会话的浏览器页面。首次启用 WSL 可能需要授权和重启，请回到同一 Windows 账号继续。安装版和源码用户各自保存项目与聊天记录。
- **直接运行 Studio 源码**　已有项目沿用原用户和原数据目录，在另一个终端用 `.venv/bin/python -m studio url` 取得当前服务的登录地址。命令见[源码启动](#兼容启动与升级)。

## 查看已有 QQ 和 Windows 桌宠

已有 NapCat/OneBot 实例可从「我的应用」打开。在「运行状态」的「服务管理」找到 NapCat，点击「管理」核对账号登录。用允许私聊的账号发消息，或在群里 @ 机器人。在 QQ 客户端确认回复后，到该应用的「任务流」打开同一请求，查看模型、工具与投递记录。[登录与排查](qq.md#qq--napcat)

Windows 桌宠先从原生客户端启动。在「我的应用 → 接入已有应用 → 连接已安装应用」选择桌宠安装目录。
支持此接入的原生后台会提供私有工作台连接文件；旧版未提供时需要更新原生后台，
工作台不会自动覆盖安装。接入只建立管理连接，不复制应用或开启开发任务。
客户端后台在线时可查询原有历史；完全退出后显示连接不可用，重新启动再刷新。

在支持用户设置的应用中，打开「模型与行为」选择现有模型方案，或修改人设及回复风格。先查看修改，再确认保存。
保存不会打断对话；重启对应应用后，点击「核对生效状态」。若提示配置已经变化，先重新
读取，再决定如何修改。模型账号、权限与工具等更详细的设置仍在原管理入口维护。

## 使用统一工作台

打开 Studio 默认进入「我的应用」。点应用行进入控制台，从「任务流」查看业务请求，从「测评」发起测试。
在异常业务请求或失败用例中点击「发起 Harness 修复」，核对来源和预期后再开始。修复步骤和命令日志在本应用查看。

点击「创建应用」，写下需求并生成首版方案。在应用改进中检查范围与验收条件，核对目标平台、安装后入口、所需服务和首次绑定，再确认。
需要把应用装到其他电脑时，使用本应用的「下载与部署」。现有仓库、组件和 Studio 项目继续按来源管理。
共享模型连接、方案、开发账号和项目级熵回收从「平台管理」进入。

统一入口的 QQ「应用改进」用于提出名称和回复要求的配置提案，点击确认后才保存。
本机试聊和 QQ 实际收发的操作见[创建 QQ 官方机器人](#创建-qq-官方机器人)。旧进程如提示缺少试聊身份，需要手动停止后重新启动。

桌面应用在同一工作台的「应用改进」中开发并生成安装包；已有 Studio 项目及对话直接保留。在「接入已有应用」选择导入桌宠开发源码，可显式导入本机已安装 Live2D 的公开源码基线；导入完成后也进入同一个应用工作区。

带启动清单的新构建可在应用「下载与部署」页选择对应构建，点击「选择并校验已安装程序」，通过 Windows 文件选择器选中已安装 EXE；校验成功后保存程序绑定，但启动仍禁用：准备的运行依赖缺少独立可信的校验依据。没有安装时先下载并自行安装，不选择安装器 EXE。旧构建、仅导入的 Live2D 或已切换运行版本须使用原客户端入口；启动请求不等于模型及窗口已经验收。
完整能力和 API 边界见[Console 参考](../reference/console.md#统一应用工作台首期)。

## 先连接模型

在「平台管理 → 模型连接与凭据」填写聊天模型、连接地址和自己的凭据，或选择已支持的 Codex / ChatGPT 连接。首次接入产生的模型费用属于所选连接。标准应用的配置和运行不要求开发账号；只有需要写代码的开发任务才要求配置开发模型并登录 Codex 开发账号。聊天连接成功不能证明开发账号已经就绪，也不能证明 QQ 平台已经连接。

在「平台管理 → 开发账号」查看聊天与开发授权状态。先配置对应模型用途，再显式打开本机 Codex 授权窗口；授权入口不改写模型连接。API 聊天、开发 worker 和测评模型是不同用途，不必为了配置 QQ 应用登录开发账号。

统一工作台显示的默认模型方案也适用于需求讨论，无需为启动助手再次保存或复制模型文件；已保存配置仍优先。

保存模型配置期间可以继续编辑；本次提交完成后，新修改仍留在草稿中，需要再次点击「保存配置」。离开页面、刷新或关闭窗口时，未保存的修改或尚未返回结果的保存会触发确认。确认离开只丢弃未提交的草稿，已经提交的保存会继续处理。

## 创建 QQ 官方机器人

点击「创建应用」，说明要做 QQ 官方机器人及其用途和回复要求，例如“做一个项目答疑机器人，只回答我提供的项目说明，不确定就说明不知道”。确认首版方案的应用形态为「QQ 官方机器人」后，点击「确认并应用配置」；之后仍可在聊天中提出调整。标准配置走应用管理接口，不为更改回复要求生成一个新的开发任务。

在该应用的「渠道与工具」填写名称、回复要求、AppID 和 AppSecret，点击「保存配置」。AppSecret 只填专用密码框。在「运行状态」点击「检查」核对本地配置，再点击「启动」。

用户需要先在 [QQ 官方平台](https://bot.q.qq.com/wiki/develop/api-v2/)拥有机器人，并按后台要求配置权限、允许的测试范围等。这里不是 NapCat / OneBot 登录，不使用个人 QQ 扫码替代官方机器人凭据。平台申请、审核、账号权限和公开上线不由工作台自动完成。

应用启动后，可在「运行状态」的「应用试聊」检查聊天模型如何回复，回答显示在当前工作台。要验证平台收发，请在 QQ 平台允许的测试账号或群中发送一条消息，并在 QQ 客户端确认收到回复。遇到问题时分别核对平台凭据、权限、网络和模型连接。

MVP 在本机运行，电脑关机或休眠会影响服务，不提供云端全天托管。需要新增协议、工具或业务逻辑时仍属于代码开发，应进入既有 Harness 和独立验收流程；不支持的能力不会因为填写一段描述而自动出现。

## 把应用交给另一台电脑

1. 从「我的应用」打开目标应用的「下载与部署」，选择**接收方**的操作系统。页面列出运行要求、首次要绑定的账号和可用版本。服务型应用通常要求 Docker 与 Compose v2，Windows 端使用 Linux 容器。
2. 如页面提供「下载安装包」，直接下载所选版本。支持构建的来源也可展开「生成安装包」，选完整 Git 提交或本应用已独立验收的 Harness 任务，再为目标平台生成。可以从「校验与运行记录」核对包摘要和构建来源。
3. 接收方运行 Windows x64 的 EXE，或用 `bash` 执行支持 Linux x64 的 RUN 文件，按提示绑定自己的模型与渠道。在接收方客户端试用一项实际功能。支持回执导入的应用还可在「校验与运行记录」导入安装器生成的 JSON，核对本次安装和服务健康检查。

各类应用的启动方式、源码输入和接收方依赖见[工作台应用安装包](../reference/delivery.md#工作台应用安装包)。

## 开发桌面应用与已有 Live2D


在「创建应用」写下希望制作的桌面应用、界面、数据和 Agent 行为。在「应用改进」核对 Windows 桌面应用形态和首版方案，确认后开工。例如先做一个带文字输入的桌面助手，再逐步加入角色展示和所需工具。需求讨论、开发、独立验收和打包都在该应用中继续；关闭页面后可以从「我的应用」回来查看，不需要重新发送需求。
单次需求最多 16000 个字符，超出时保留全文供精简，不会截断或发送。服务器明确拒绝的输入会回到可编辑草稿；
网络中断等未确认结果继续保留原请求编号，刷新原记录核对，不自动创建另一条需求。

构建下载在同一个打开的文件上核对摘要并逐块复核，支持范围续传；文件被替换不会改为下载替换物，不会发送未通过复核的内容。下载不另存一份临时安装包。

完成后下载已就绪的 Windows 安装包，自行安装。生成的应用包含已验收的应用实现、所需运行源码和桌面宿主，使用自己的模型连接与本机数据；对方需要 Windows、首次下载运行依赖的网络及模型授权。打包成功不代表已安装、窗口已运行或真实模型交互已经验收。

从「我的应用 → 接入已有应用 → 导入桌宠开发源码」点击「选择并导入桌面伙伴」。确认后，工作台在标准安装目录和原生构建目录中核对本机桌宠的版本。找到唯一匹配项会直接连接，其他情况会打开 Windows 文件选择窗口。开发基线来自该安装的公开源码与配套载荷。首版可以改角色提示词、桌宠文字输入适配、头像行为和设置界面；固定上游资源按原构建输入核对。试用副本单独安装，使用独立配置和数据。开发账号、资产版本或安装包检查失败时，在原会话查看原因。时间尚有剩余时，用户点击重试可为已耗尽轮次的任务增加一次机会，累计 60 分钟上限持续生效。统一工作台不自动执行已安装的程序来检查运行情况；请在桌面客户端确认窗口和实际交互，历史运行记录不能代表当前状态。完整开发候选和筛选后的 Windows 安装源码各有独立摘要。安装目录的 `resources/runtime-payload/source` 保存应用的对应源码，`resources/desktop-source` 保存实际用于打包的 Electron 宿主源码、构建脚本和依赖锁。桌宠另在 `resources/desktop-host` 随附试用版的启动脚本。

导入请求有固定编号。刷新只查询原请求，不会重新弹窗；等待中的请求可显式继续同一编号。选择中断且来源未知时，先关闭旧 Windows 选择窗口，再确认重新选择；已有来源则继续核对原来源，不自动改选。导入失败、取消和成功分别显示，不把导入成功说成已安装或已运行。

原开发任务及记录可在同一应用中查看。失败任务仅在当前版本及冻结验收证据有效时允许重试；缺失、损坏或已被新版本替代的旧证据只读保留，并说明原因。不要删除历史文件来绕过恢复检查。

若未完成旧任务的来源或证据暂时无法核对，工作台保留原状态和答复，不自动重新开发；
该应用暂停新请求，其他应用仍可使用。先核对原版本、任务记录和冻结证据，恢复后再刷新或显式重试。
读取记录不会补建缺失任务库或修改旧目录权限；旧失败记录则可以保留，并在同一应用提出新的明确需求。

## 从源码构建

从 Windows + WSL2 的仓库根目录运行以下命令。两个输出目录必须是新目录。构建使用本机 Windows Node 或下载锁定版本，缓存可用参数 `--windows-build 'D:\\AgentStrataBuild'` 指定。

```bash
.venv/bin/python -m studio.build studio --output /tmp/studio-installer
.venv/bin/python -m studio.build reader --output /tmp/reading-sample
```

构建工作台安装包前，构建端需已准备 Console 的 Node/npm 和前端依赖。打包会从当前源码重新编译生产页面并随源码一起交付；构建失败或期间源码变化时停止打包。安装准备直接使用包内页面资源，旧的仅源码安装包仍沿用本机编译流程。

新建应用的开发仓库只保留该应用、运行源码和应用回归；后续改动继承已验收版本及其功能测试。框架变更仍在工作台仓库执行 `full`。已有桌宠继续使用实际安装的完整公开基线。

各目录中的 `application.exe` 是可安装产物。直接构建的读书助手属于源码示例。在工作台对话中交付的安装包另有与实际验收候选绑定的构建回执。规格见[桌面开发工作台](../../specs/desktop-app-studio/spec.md)。


## 兼容启动与升级

WSL 发行版属于各自的 Windows 账号。首次准备会在运行工作台的同一 Windows 账号下安装 Ubuntu；如果系统 WSL 组件尚未启用，先由管理员完成系统准备，再回到原账号注册发行版并重试。工作台不会借用另一个管理员账号安装发行版；重启后也应回到原账号继续。

源码启动先构建 React 前端，再以原用户和原数据目录启动统一工作台：

```bash
npm --prefix console/web run build
.venv/bin/python -m studio serve --home "$HOME/.local/share/agentstrata/studio"
.venv/bin/python -m studio url --home "$HOME/.local/share/agentstrata/studio"
```

`url` 命令先核对当前工作台与启动记录，只在验证通过后返回地址；未启动、旧记录或端口被
其他服务占用时返回失败。不要手工使用 `launcher.json` 的旧地址绕过检查。打开返回的本机
地址完成会话认证，不分享其中的登录令牌。Windows 启动器验证当前服务进程后才记录升级版本。
旧页面暂以同一命令增加 `--legacy-ui` 保留作为迁移回退；常用桌面创建、Live2D 导入与有有效证据的任务恢复已经在统一页面提供。真实安装升级验证完成前不删除兼容入口；不要同时启动两个页面服务。
Windows 安装版继续使用原来的独立 WSL 用户和项目目录，不自动导入源码开发用户的项目。
Windows 入口以 WSL 进程退出码判断成功或失败，标准错误流中的提示不会单独中断启动；
非零退出仍显示错误原因。安装路径保留字面值，空格、中文、美元符号和反引号不会被默认 Linux shell 解释。
旧 Windows 程序仍在不代表其 WSL 发行版和项目库已恢复。真实迁移前须核对原发行版、专用用户
和项目库位置；不能新建空库或把另一个用户的缓存当作原项目。缺少原环境时先确定授权的隔离验收目标，
不要自动安装发行版、合并目录或改私有权限。

升级遇到运行中旧版本、未完成开发任务或无法识别的任务状态时会停止准备，不会强制停止服务。先从原安装入口完成或处理任务，再明确停止旧工作台后升级。旧安装缺少运行版本记录时，必须先处理原任务；不要删除任务库或改目录权限绕过保护。生产前端资源在准备环境时构建，失败会保留原因供排查。
升级检查发现 Studio 项目库仍处于 WAL 模式时，会在打开数据库前停止，保留原主库及辅助文件。
由原库所有者核对并提供不依赖 WAL 的一致副本后再升级；不要忽略日志、删除辅助文件或自动修复原库。

若提示开发消费者仍占用项目库，等待原工作台的当前步骤完成退出后再重试；即使网页服务已经停止，
开发线程仍可能在收尾。准备期间复用同一消费者锁，直到新入口就绪，不改旧任务或强行释放锁。
同一版本和前端资源已经就绪时，再次打开工作台不会打断消费者。

旧任务的来源元数据只读检查不会初始化或修复任务库。原库若仍处于 WAL 模式，历史保持只读阻断，
由原有任务库的所有者完成日志收尾后再核对；查看历史不会自动 checkpoint、创建共享文件或补建缺失任务。

## 开发者入口

工作台 UI、对话提案与确定性应用接口复用同一生命周期，不在聊天里拼接 Shell 命令。配置草案与真实连接操作分开，标准应用不得依赖开发 worker 登录。接入流程的设计与验收条件见[工作台规格](../../specs/desktop-app-studio/spec.md)；编写适配或管理操作时可使用仓库的 [Agent 应用集成技能](../../.agents/skills/agent-application-integration/SKILL.md)。

配置验证、受控平台测试、真实 QQ 往返和公开发布分别验收；不把模拟响应或模型文本当作已完成交付。
