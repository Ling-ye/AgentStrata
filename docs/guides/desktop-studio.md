# 在本机创建、运行和改进 Agent 应用

在 Windows 11 x64 上打开 AgentStrata 开发工作台安装包，完成安装并从开始菜单启动。在向导中选择准备环境。它使用 Ubuntu 24.04 / WSL2 的独立开发用户，首次启用 WSL 时按 Windows 提示授权和重启。再次打开同一入口会继续准备。网页、项目、聊天记录都留在本机。

## 使用统一工作台

从 Console 打开的 AgentStrata Studio 默认进入「我的应用」。选择应用后，在同一个工作区
查看概览、使用说明、配置、记录与改进；原有服务诊断、实例配置、测评和 Harness 在「高级管理」中继续可用。
首期可在「创建应用」新建 QQ 官方机器人，并在「模型与连接」维护其模型连接。
已有仓库实例、组件安装和 Studio 项目按原来源管理，不需要重新创建或迁移配置。

统一入口的 QQ「改进」对话用于提出名称和回复要求的配置提案，点击确认后才保存。
AppSecret 只填专用配置框。QQ 应用启动后可在「使用」中进行独立试聊，不会把消息发送到 QQ。旧进程如提示缺少试聊身份，
需要手动停止后重新启动。试聊、检查和进程状态都不代表真实 QQ 收发成功。
已有桌面应用开发、连接本机 Live2D 和安装包生成仍使用下面的原 Studio 入口。带启动清单的新构建可在统一应用「使用」页选择对应构建，点击「选择并校验已安装程序」，通过 Windows 文件选择器选中已安装 EXE；校验成功后保存程序绑定，但启动仍禁用：准备的运行依赖缺少独立可信的校验依据。没有安装时先下载并自行安装，不选择安装器 EXE。旧构建、仅导入的 Live2D 或已切换运行版本须使用原客户端入口；启动请求不等于模型及窗口已经验收。
完整能力和 API 边界见[Console 参考](../reference/console.md#统一应用工作台首期)。

## 先连接模型

在「模型与账号」填写聊天模型、连接地址和自己的凭据，或选择已支持的 Codex / ChatGPT 连接。首次接入产生的模型费用属于所选连接。标准应用的配置和运行不要求开发账号；只有需要写代码的开发任务才要求配置开发模型并登录 Codex 开发账号。聊天连接成功不能证明开发账号已经就绪，也不能证明 QQ 平台已经连接。

## 创建 QQ 官方机器人

点击「创建 Bot · QQ 助手」，在同一聊天页面说明用途和回复要求，例如“做一个项目答疑机器人，只回答我提供的项目说明，不确定就说明不知道”。Agent 提出配置后，核对内容并点击「应用这份配置」；之后仍可在聊天中提出调整。标准配置走应用管理接口，不为更改回复要求生成一个新的开发任务。

在连接卡中填写应用名称、用途与回复要求、AppID 和 AppSecret，点击「保存连接」，再使用「检查配置」核对本地条件。AppSecret 只在专用输入框填写，不要粘贴进聊天。凭据不会随配置提案返回给模型或作为明文状态展示。

用户需要先在 [QQ 官方平台](https://bot.q.qq.com/wiki/develop/api-v2/)拥有机器人，并按后台要求配置权限、允许的测试范围等。这里不是 NapCat / OneBot 登录，不使用个人 QQ 扫码替代官方机器人凭据。平台申请、审核、账号权限和公开上线不由工作台自动完成。

点击「启动」后查看运行状态，在平台允许的测试账号或群中发送一条消息，确认 QQ 内收到回复。**配置检查通过只代表本地配置满足条件，运行中只代表应用进程状态；都不能代替真实试聊。** 发生错误时核对平台凭据与权限、网络和模型连接，再执行重试。点击「停止」结束本机应用运行。

MVP 在本机运行，电脑关机或休眠会影响服务，不提供云端全天托管。需要新增协议、工具或业务逻辑时仍属于代码开发，应进入既有 Harness 和独立验收流程；不支持的能力不会因为填写一段描述而自动出现。

## 开发桌面应用与已有 Live2D


点「新聊天」并说出需求，例如“做一个读书助手，可以添加书名、勾选已读，也能让助手帮我标记”。同一段聊天继续改这个应用。改动经过开发和独立验收后生成 Windows 安装包。点击「试用桌面版」安装该构建，或将「下载 Windows 安装包」得到的文件交给另一位用户。对方只需要 Windows、首次下载运行依赖的网络以及自己的模型连接。

点击「连接 Companion · 桌面伙伴」后，工作台在标准安装目录和原生构建目录中核对本机桌宠的版本。找到唯一匹配项会直接连接，其他情况会打开 Windows 文件选择窗口。开发基线来自该安装的公开源码与配套载荷。首版可以改角色提示词、桌宠文字输入适配、头像行为和设置界面；固定上游资源按原构建输入核对。试用副本单独安装，使用独立配置和数据。开发账号、资产版本或安装包检查失败时，在原会话查看原因。时间尚有剩余时，用户点击重试可为已耗尽轮次的任务增加一次机会，累计 60 分钟上限持续生效。点击「检查桌面是否已启动」会核对本机实际运行的版本。完整开发候选和筛选后的 Windows 安装源码各有独立摘要。安装目录的 `resources/runtime-payload/source` 保存应用的对应源码，`resources/desktop-source` 保存实际用于打包的 Electron 宿主源码、构建脚本和依赖锁。桌宠另在 `resources/desktop-host` 随附试用版的启动脚本。

## 从源码构建

从 Windows + WSL2 的仓库根目录运行以下命令。两个输出目录必须是新目录。构建使用本机 Windows Node 或下载锁定版本，缓存可用参数 `--windows-build 'D:\\AgentStrataBuild'` 指定。

```bash
.venv/bin/python -m studio.build studio --output /tmp/studio-installer
.venv/bin/python -m studio.build reader --output /tmp/reading-sample
```

新建应用的开发仓库只保留该应用、运行源码和应用回归；后续改动继承已验收版本及其功能测试。框架变更仍在工作台仓库执行 `full`。已有桌宠继续使用实际安装的完整公开基线。

各目录中的 `application.exe` 是可安装产物。直接构建的读书助手属于源码示例。在工作台对话中交付的安装包另有与实际验收候选绑定的构建回执。规格见[桌面开发工作台](../../specs/desktop-app-studio/spec.md)。


## 开发者入口

工作台 UI、对话提案与确定性应用接口复用同一生命周期，不在聊天里拼接 Shell 命令。配置草案与真实连接操作分开，标准应用不得依赖开发 worker 登录。接入流程的设计与验收条件见[工作台规格](../../specs/desktop-app-studio/spec.md)；编写适配或管理操作时可使用仓库的 [Agent 应用集成技能](../../.agents/skills/agent-application-integration/SKILL.md)。

配置验证、受控平台测试、真实 QQ 往返和公开发布分别验收；不把模拟响应或模型文本当作已完成交付。
