# 测评执行与结果链路

## Summary

统一单题执行、评分和结果交接，防止正常评分结果因字段类型错误丢失。
开始测评与结果页面直接显示预期回答、行为和校验要求。新运行使用结果格式 v2；
旧记录原地归档，只保留摘要和原始导出，不迁移、补判或恢复。

## Design

遵循 [四层运行时基线](../runtime-four-layer-definition/spec.md)。Evaluation 是独立配套
模块：application 管理生命周期，Core 管理执行组、预算、监督进程和权威结果，适配器
提供执行观测与评分，Console 只查询展示，Harness 只通过公开接口读取可修复的新结果。
沿用现有服务、UDS、SQLite、隔离进程及 artifact 所有权，不增加运行时消息层。

单题依次冻结预期、执行、保存执行观测、评分、保存评分观测、校验和持久化。
插件不组装最终 Trial；单题不再嵌套启动 Suite。结果类型和编解码是唯一契约，
包含 expectation、execution、assessment 和结构化 error；无错误用 null，未评分
分数用 null，实际零分保留。执行、评分和总耗时分开，未知值不补零。
现有各题原生与语义评分规则不变，评分不能覆盖真实工具、状态或权限事实。

执行和评分快照复用受约束的 observation 通道，只保留已校验、脱敏的事实。
后续失败不能丢弃已保存证据；快照不构成可重放模型回合或完整 Target 组检查点。
单题执行、评分异常及 Case 超时继续，回答不符合要求为 failed；结果契约、IPC、
权威持久化和进程树清理异常终止整批。取消、总预算及完整 Target 组语义保持。
异常由实际边界标记，不能根据最后的 judging 阶段推断异常一定来自评分模型。

结果文件和服务结果标记 schema_version: 2，插件协议升级到 v2。现有 HTTP 操作路径与
UDS 分帧 v1 保持；分帧未改变，既有服务的维护握手仍可用于同步切换，结果不做旧格式转换。
SQLite 只索引验证后的新结果。旧文件和数据库行不改写；旧记录不进入新趋势、
比较、恢复或 Harness 来源，旧 Case 实例 ID 明确返回归档说明。升级复用维护机制，
在相关 Evaluation/Harness 工作空闲时切换，不自动部署或重启运行实例。

预期由受信题目、评分规则和 fixture 形成一个轻量投影。精确答案、预期行为及
校验要求分别展示，无唯一文本答案时明确说明按行为或状态校验。动态值只在解析并
冻结后显示；不得从实际回答反推预期。结果读取本次快照，不能回读最新题库替换。
该投影只进入操作者展示和评分，不能额外注入被测模型。

测评列表默认显示输入和预期摘要；结果列表并列显示预期与实际回答。详情按实际
输入、预期/实际对照、执行事实、评分和错误展开；底层元数据可折叠。使用现有 Arco
组件，窄屏上下排列，未评分和未记录明确展示，生命周期与判定分别显示。

## Acceptance

- 受控通过与未通过结果均可经真实监督进程、IPC、持久化和读取正常返回。
- 非法字段产生可定位的契约异常，已有回答和评分证据保留；系统故障不启动下一题。
- 执行/评分异常、Case 超时、总预算、取消、进程清理和完整组检查点保持真实语义。
- 各执行器使用共同结果组装，评分来源、事实失败、零分和未评分可区分。
- 开始测评与结果页默认可见预期，修改题库不改变已保存预期，预期不泄漏给被测模型。
- 新记录可查询、导出和按条件进入 Harness；旧记录只归档导出，既有数据不改写。
- 保留现有手动入口、题库、评分规则和部署边界；无暂存、提交或真实实例修改。
