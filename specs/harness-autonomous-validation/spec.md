# Harness 自动修订与完整验收

## Summary

Harness v4 在冻结前试运行和修订复现方案，按不可缩减的用户预期组合验证。
旧记录只读保留；当前协议内的接续继承已用预算。新任务的交付与清理见
[PR 交付契约](../harness-pr-delivery/spec.md)。

## Design

遵循 runtime-four-layer-definition：Channel 保持资源取材和网络边界，Application
负责物化，Agent 通过 AgentTask.resources 接收图片并产生发送回执；Evaluation
拥有私有 Case 图片及真实执行评分，Harness 只经公开服务入口登记及执行。
Console 负责呈现准备版本、验收覆盖和补充图片，不作技术归因或评分。

准备循环保存每版草案和结构化执行证据。收集、fixture、环境及证据错误先反馈给
准备执行器；同一草案不重复执行。产品领域异常保留类型、稳定代码和因果链，
需用具体可观察结果断言表达，不能把任意异常转成产品失败。源代码在此阶段只读。
冻结后的测试不能就地变更；修订必须重新验证原基线与候选。

完整参考答案保留原文；图片任务必须覆盖物化、真实视觉发送和语义验收。
组合计划分别指定各检查的重复次数；真实 Agent 至少三次并独立确认。
图片保存在受信宿主的私有材料中，引用必须绑定来源作用域及内容摘要。
纯文本 Case 身份保持不变，私有图片不进入公开回归或 Git。
缺失原图进入等待输入，补充后恢复同一逻辑任务。所有子验证退出均记录终态。

## Acceptance

- 自动修订虚构接口、fixture 错误、错误异常表达及覆盖缺口；重复失败和预算耗尽明确停止。
- 环境错误不能成为产品失败；遗漏图像发送或语义失败不能成为 fixed。
- 补图校验类型、摘要、作用域；不给参考答案注入目标输入，不弱化公网/TLS/权限校验。
- 保留历史、幂等接续和累计预算；不扩展 Git、部署或框架自修改权限。
