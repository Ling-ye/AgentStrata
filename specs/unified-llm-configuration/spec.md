# 统一模型配置与能力发现

## Summary

AgentStrata 的模型连接、配置方案和用途绑定由一个宿主配置库维护。机器人、辅助
Agent、独立 worker、Harness、Evaluation 和代码熵回收通过同一解析入口取得不可变
模型路由。Console 使用同一个服务查询模型能力、编辑方案和保存当前配置。

## Design

遵守[四层运行时](../runtime-four-layer-definition/spec.md)与
[六层源码依赖](../domain-layered-dependencies/spec.md)。Contracts 定义共享路由；Core
管理配置快照、凭据引用和单次推理；厂商适配器负责发现和协议转换；宿主保留 Agent
循环、权限、任务生命周期和交付。统一入口不把 Codex 原生执行循环改成普通模型请求。

配置分为连接、方案和用途绑定。连接声明协议、端点和认证引用；方案声明模型、推理
强度、上下文和请求参数；用途只引用方案。秘密保留在私有凭据存储或环境文件。
配置保存必须原子化并检查版本，不能让并发编辑覆盖他人的保存。

### 权威配置和共享入口

- 宿主配置默认位于 `~/.config/agentstrata/llm.json`，可由
  `AGENTSTRATA_LLM_CONFIG` 指定绝对路径。部署向机器人、Console、Evaluation 与
  Harness 投影同一个路径；worktree 和隔离任务不另行维护一份可变配置。
- 配置包含 `connections`、`profiles`、`bindings` 与单调递增的 `revision`。
  模型目录是可更新缓存，与操作者保存的方案分开。公开仓库只保留无秘密示例。
- 连接包含 adapter、API 类型、端点和认证引用。Codex 连接可引用现有 main/worker
  凭据；由可信调用用途选择 lane，复用模型方案不合并 refresh lineage。API Key 使用
  一处私有环境文件中的引用，不在各服务重复保存实际 key。
- 方案包含连接引用、模型、推理强度和已支持的可选参数；用途包括机器人主模型、
  research/search/subagent、独立 code worker、Harness、code health、测评目标及
  judge。默认引用共享方案，允许显式选择另一方案；不增加多层隐式继承。
- 扩展已有 `ResolvedModelRoute` / `ModelSelection` 承载方案标识、配置版本和
  上下文配置；保留 `ModelClient` 与 Runtime adapter 的分工。共享解析器只产生
  不可变快照，SDK、认证、重试和协议转换由同源 adapter 装配入口拥有。
- API 推理继续复用现有 Chat Completions / Responses 客户端，Codex 执行继续使用
  原生 App Server。Harness 当前要求 Codex 执行能力，选择器按用途筛选可用方案；
  普通 API 连接不会因进入统一库而自动获得代码执行能力。

Codex 使用实际执行连接的 App Server `model/list` 发现模型和推理强度，仅在实际
结构化接口明确返回时补充上下文能力。目录按凭据身份和客户端隔离，不能使用桌面
账号的缓存冒充 worker 能力。OpenAI 兼容 API 查询其模型接口；没有返回的能力标为
未知且不可配置，不提供人工补充，不根据模型名称猜测上限。不维护全局推理强度枚举。

目录记录来源、连接身份、客户端版本、发现时间、模型标识、显示名、默认与可选推理
强度、输入模态以及可选上下文信息。所有能力保留接口来源，未知不解释为零或不支持。
本机缓存检查只用于诊断，不作为接口未声明能力的配置依据。运行事件观测到的实际
窗口可只读展示，但不等于允许用户设置的最大值。不抓取文档网页作为运行期目录，
也不调用模型生成答案来推断能力。

发现协议依据 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 的
`model/list`；普通 API 模型列表依据 [Models API](https://developers.openai.com/api/reference/resources/models/methods/list)。
后者没有提供通用上下文或推理强度元数据契约。

首次读取或缓存超过 15 分钟时刷新，Console 支持主动刷新；相同连接的并发刷新合并。
新增连接和认证身份变化使旧目录失效。目录失败与登录失效分别呈现；刷新失败不得将
目录清空或伪装成当前成功结果。无成功目录时不提供伪造下拉选项。

上下文显示区分厂商报告的默认窗口、最大窗口及运行观测值。只有实际接口明确声明
可设置窗口及其范围时，才提供对应配置并经 adapter 传递。普通 API 的本地上下文
预算仍属运行时策略，不能当作模型能力或未经支持的请求字段发送。未知字段不可配置；
模型变化时清除不适用的旧参数。

### Console 和保存

- 增加统一「模型配置」页面，管理连接、方案与用途引用。顺序为选择连接、刷新目录、
  选择模型、选择推理强度、查看上下文并按需调整、保存方案和用途绑定。
- 后端公开配置读取与版本化保存、目录读取与主动刷新、有效路由解析三个服务操作。
  Console 通过 `/api/llm/config`（GET/PUT）、`/api/llm/catalog`（GET）、
  `/api/llm/catalog/refresh`（POST）和 `/api/llm/resolved`（GET）调用。
- 保存校验当前模型和能力、引用完整性及配置版本；冲突返回 409，保留浏览器草稿。
  目录刷新不产生配置版本；被引用方案不能直接删除。
- 机器人、Harness、测评和熵回收页面复用同一个方案选择组件，展示有效模型和参数，
  编辑动作跳转统一页面。移除各页独立模型列表和硬编码推理选项。
- 参数字段根据实际接口声明的能力显示；API 返回能力不足时显示「接口未提供」，
  不接受人工补充或通过直接请求绕过校验。API Key 等秘密仅通过私有配置入口写入，
  目录响应和任务快照只含引用。
- 写接口沿用 Console 本机、同源操作限制；配置响应禁止缓存。页面覆盖加载、空目录、
  失效选择、过期目录、保存失败、长模型名称和窄屏。

目录刷新不改变已保存的模型选择。失败保留上次成功目录并显示时间和错误；模型下架
不自动切换。配置方案保存后用于下一轮对话和新任务，执行中的任务使用冻结路由。
Evaluation 同时冻结被测模型、辅助模型和评分模型，历史结果不回填当前配置。

每次机器人 turn 在完成身份准入后、创建模型副作用前解析一次配置版本，同一 turn 的
主模型和辅助模型使用一致快照。不得在共享客户端上调用 `set_model` 改变其他会话。
路由变化按现有会话绑定机制更新；不能复用原生状态时重建执行会话并保留宿主管理的
对话历史、人格和记忆。正在执行的旧实例在本轮结束后释放。

Harness/测评/熵回收在创建任务或批次时冻结全部相关方案，重试及恢复沿用该快照。
周期调度保存用途或方案引用，每次创建新任务时读取当前版本。冻结记录保存实际
provider/model/effort/context 与版本指纹，不仅保存可变 profile ID，不持久化 token。

迁移一次性收集旧 BotSpec、环境文件和 Harness 配置中的有效模型配置，保留原有用途
差异，写入统一库并移除旧入口。迁移不删除历史任务或登录凭据，不修改操作者日常
Codex 配置，不启动任务、部署、提交或发布。

旧配置若含接口无法确认的可选参数，迁移报告逐项列出，并在新方案中省略该参数，
交由 provider 默认行为处理；历史冻结记录原样保留。模型本身未出现在返回目录中时
该用途标为不可用，不能静默切换为另一模型。

实施顺序为共享配置与发现、全部消费方接入、Console、迁移及旧入口删除，完成前不
切换线上运行。迁移先 dry-run 生成差异，再备份并执行；凭据引用集中，现有秘密不进入
报告。移除旧 `llm.*` 具体模型字段、`*_MODEL`/`*_REASONING_EFFORT` 等覆盖入口及
独立 Judge/Harness 模型设置；BotSpec 和调度只保留用途或方案引用。运行时预算、
执行权限和业务配置不混入模型迁移。遇到旧字段明确报告迁移错误，不静默忽略。

运行中的任务需结束或受控停下后再做部署切换；保留历史任务原始冻结记录，不借本次
迁移清空 Harness/Evaluation 数据。实际线上切换和真实 QQ 验收单独执行。

## Acceptance

- 所有运行中的模型调用通过同一配置解析和 adapter 入口；各用途可引用相同或不同方案。
- Console 模型与推理选项来自服务端目录，切换连接或模型不会保留不适用选项。
- 保存、读取和实际执行使用同一份配置；新任务与旧任务配置变化相互隔离。
- main/worker 凭据隔离、宿主工具权限、模型 continuation 和历史证据边界保持。
- 旧模型配置入口显式退役，无双写或静默回退。

## Verification

覆盖配置持久化和并发保存、目录分页和失败、未知能力、模型下架、真实调用参数、
跨用途共享、下一轮生效、任务冻结以及旧配置迁移。运行相关 Python/Console 测试与
仓库 full 检查。真实模型发现、推理与 QQ 交付分别记录，不用 mock 代替。
