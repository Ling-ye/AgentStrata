# 评测结果与进步趋势

## Summary

测评中心在现有 Agent 能力与 QQ 链路两条轨道上，展示单次通过情况、逐测试点结果和历史变化曲线。继续使用唯一 Evaluation service 与现有 artifact，不新增数据库或独立生命周期。Comparison 与其他 Suite 历史记录仍可查询、导出和操作。

## Design

### 趋势交互与累计耗时修正（2026-09-10）

- 遵循 [四层运行时基线](../runtime-four-layer-definition/spec.md)，本次仅调整 Evaluation 的采集和只读展示，Agent 判分继续使用 DeepEval，不变更模型配置、题库或机器人运行链。
- 范围筛选与刷新、拆线维度、图表指标分别放置。指标在图表标题旁通过单选按钮切换，分组勾选不承担指标选择。
- 耗时是选中 Target 下 Case 与重复执行的累计执行阶段时间，不含 DeepEval 判分，也不是整次评测墙钟时长。QQ 合成链使用自己的累计链路时间；其无模型 Target 不因 model 为空被排除，但不可冒充实际 Agent 模型执行。
- 后端返回累计完整值、已记录小计、完整样本数、部分样本数和应记录数。历史缺项不导致已采集的小计消失；仅部分记录时显示“至少”和覆盖数，用空心点表示，不与完整耗时点连线。零值可用，未记录、无效值不填零，不从总耗时或当前记录反推历史 Agent 耗时。
- 运行端在实际驱动入口开始计时并在 finally 结束；执行异常和后续判分失败保留执行时间。超时或取消由已有监督进程在请求终止时记录已观察区间，标为部分时间；判分阶段中断保留先前完成的执行计时。预检失败和未进入执行的 Case 不伪造耗时。
- 复用现有 observation IPC、Trial 与摘要查询，保持失败/取消、进程回收及 artifact 所有权。读取历史只计算投影，不重写原始结果。

- Application 在成功预检后、创建记录时，将创建时间、Git HEAD 与工作区是否有未提交内容保存到自己拥有的 `request.json`。Git 不可用时记录未知，不影响评测；历史记录不补写当前版本。只记录 commit、布尔状态和时间，不读取或展示 remote、分支、作者、文件名和 diff。该快照标识创建时代码，不承诺运行期间外部代码未变化。
- `GET /api/evals/evaluations` 与现有详情接口增加只读 `insights` 与 `source_revision` 投影。后端从已持久化 Trial 汇总通过、失败、异常、跳过、已记录与计划次数，详情仍按既有接口读取。无法确认的计数不补零为成功；记录标识重复、结果不完整或缺少必要元数据时明确标识。
- 通过率采用通过次数 / 全部已记录测试次数，分母包括失败、异常和跳过。每次重复执行分别计数，页面同时展示计划次数和已记录次数。生命周期 completed 与产品 verdict 分开展示，关键门禁失败保留原始 verdict，不合成为智能分数。
- 趋势按用户勾选的 Agent（实例与 Backend）、模型（含推理强度）和测试规模拆线，全部取消时合并为一条时间曲线。Git、配置、Case 集合及判分版本作为每点信息保留，不强制分组。每点为 Evaluation/Target；支持跨实例、时间、模型、规模与 Case 选择。展示分组不改变 CLI compare/resume 的严格定义与执行指纹。具体引擎、输入输出和指标规则见 [DeepEval 接入规格](../evaluation-deepeval/spec.md)。
- 曲线仅纳入 completed、记录数量完整、标识和结果有效、非 dry-run 且测试定义已记录的评测。取消、中断、进行中、缺少定义或不完整记录仍可在列表查看，并显示排除原因。模型提供方版本未锁定等限制使用已有快照事实，不补造历史版本。
- 前端保持开始测试、运行记录，并新增进步趋势。启动与记录使用顶部 Bot 选择，趋势独立多选。单次详情以通过概览、能力分组和可筛选测试点表格为主；展开测试点能看到已脱敏的回答、判分理由和错误。原始摘要仍可展开，取消、重跑、删除和导出保留。
- 趋势可筛选轨道、时间范围和测试条件，支持通过率/质量分/Agent 耗时切换；每个点通过键盘或鼠标打开对应记录，表格同时提供时间、commit、工作区状态、模型与配置版本。仅一个点也显示，无数据使用明确空状态。
- 列表继续消费现有查询接口；趋势不为每个历史点请求完整正文。详情按所选 Evaluation ID 请求并轮询活动任务，切换记录后的旧响应不替换当前记录。刷新不改变选中记录。桌面和窄屏均可操作。

## Acceptance

- 单次成功、失败、异常、跳过与取消均能明确辨别；部分记录不形成虚假的 100% 完整通过率。
- 相同条件下多个不同 Git 或配置版本能形成时间曲线，鼠标/键盘可定位评测；不同条件是否分线由所选维度决定；Git 不参与拆线。
- 历史缺少 Git 时按真实时间显示“未记录”，读取历史时不调用 Git；重跑捕获新的版本，幂等重试不覆盖旧快照。
- 持久化仅由 Evaluation application 写入 request，Console 不创建 worker 或模型调用；现有结果、状态及操作契约保持。
- 覆盖重复 Trial、未知 outcome、缺失/部分正文、dry-run、测试定义变化和请求切换；没有有效趋势时展示原因。
