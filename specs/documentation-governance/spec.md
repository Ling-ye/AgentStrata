# 文档结构与维护基线

## Summary

项目文档服务开发者与 AI 协作者，采用“任务入口 → 操作指南或领域说明 → 源码与必要规格”的
读取路径。一个事实由一处正文维护，人和 AI 共用领域事实。单次执行记录放在交付说明或 CI，
文档只维护现行设计、必要理由、操作与验证方法。

## Design

### 内容归属

- README 说明项目和最短开始路径；AGENTS 保留全局授权、信任与按任务读取要求。
- docs/README 是任务地图；guides 维护操作步骤；reference 维护当前领域事实和约束。
- docs/maintenance 提供文档与 SDD 工作流。specs 保留长期基线和确实未完成的设计，
  已完成普通规格提炼进现行正文后删除，旧文件和流水不另建归档目录。
- 领域页提供“源码入口”，链接相关实现、配置和测试；这些链接同时用于变更关联，不另建注册表。
- 同一操作与完整规则只维护一处；允许概览摘要。过时与重复须根据实现和契约判断，不以日期或篇幅代替判断。
- 不累计验证日期、测试计数、耗时、临时故障、重跑、机器状态或临时验证路径。
  合法版本、创建日期、配置阈值、示例、固定夹具和有设计依据的长期基准保留。

### 自动检查与治理

独立只读检查器验证本地链接、锚点、源码入口、导航可达性及明确的运行流水；输出带路径、行号
和原因的 violations。源码关联变化、长文和疑似重复仅输出 review_hints，不据此判定失真。
不执行代码块、不访问外部链接、不启动模型。检查器同时用于 docs/fast/full 和 Harness。

遵循 [四层运行时基线](../runtime-four-layer-definition/spec.md) 和
[六层源码依赖基线](../domain-layered-dependencies/spec.md)。文档治理在消息链之外，
Harness 复用冻结检查、来源、问题组、独立审核和交付；不改变机器人执行与权限契约。

扫描范围与修改范围分开。项目维护文档均可只读审查；AGENTS、Cursor、安全政策、行为准则、reference、维护规范、
SDD、检查配置与权限规则只报告 needs_decision。普通指南与说明入口可在已有候选边界内修复。
移动、删除或新增文档必须检查完整导航和保护范围；不得通过改名、忽略文件或替换检查器绕过保护。
宿主固定检查器与政策，检查器读取候选内容；候选不能修改本次执行的规则。
新治理任务使用 governance_version 6；旧快照缺少本规则与检查器，不迁移或重新判定旧记录。
普通根目录文档以精确文件挂载获得写权限，不为修改 README 开放整个候选根目录。

源码变更通过已声明的源码入口定位相关文档。语义发现必须列出文档位置、实际读取的源码依据
及具体冲突；“很久没改”不是过时证据。无需改文档时在交付证据中说明，不追加检查时间戳。
现有治理巡检按需执行，不增加定时服务或模型调用。普通说明使用定向文档检查和独立审查，
检查器及权限实现变化使用相关回归与完整验证。交互式 AI 不获得 Git 提交或发布权限。

## Acceptance

- 典型开发、配置、工具、运行诊断、测评、Harness 和 Console 任务在两次文档跳转内进入相关主题。
- 当前领域事实没有平行 AI 契约副本；旧文档删除后链接、源码引用和读取路由仍有效。
- 明确的链接错误、缺失源码入口、孤立页面和运行流水被拒绝；示例、版本和长期基准不误拒。
- 变更关联、篇幅和重复提示不强制修改没有行为漂移的文档。
- 规范可发现问题但不可自动修复；普通文档的新增、删除和重排不会绕过固定规则或授权。
- 机器人行为、公开 API、业务数据、测试基线和既有 Git 交付机制保持原有契约。

## Verification

运行文档解析、误判反例、候选根目录、导航、源码关联与 Harness 冻结保护的定向回归，
随后使用仓库 docs 和 full 检查。按典型任务核对实际阅读路径与规则归属。
检查结果保存在交付说明或仓库外日志；静态导航不证明真实模型 token、费用或质量改善。
