# 隔离修复会话与宿主验收

## Summary

角色分配与新任务协议由[多 Agent 修复](../harness-multi-agent/spec.md)取代；本规格保留历史设计背景。

机器人与 Case 修复采用持续编码会话和统一有界轮次，取消独立的递归准备循环。
默认总预算为 3600 秒、最多三个完整轮次；无法完整验收时保留候选和缺口，不自动交付。
每任务独立 worktree、沙箱和会话状态，历史 pipeline 只读，不恢复旧 worker。

## Design

遵循[四层运行时](../runtime-four-layer-definition/spec.md)、
[六层依赖](../domain-layered-dependencies/spec.md)和
[控制生命周期](../harness-control-lifecycle/spec.md)。Types 定义候选、失败和验收结果；
Repo 保存独立步骤与证据引用；Service 决定轮次和终态；Runtime 装配编码、沙箱和验证端口；
Console 只经公开查询展示状态。Evaluation 保持结果与评分的唯一所有者。

每轮作者在任务 worktree 调查和修改产品，在独立草案目录写新增测试。宿主在执行结束后冻结
候选和测试，使用同一测试分别验证原始基线与候选快照，不回滚正在修改的 worktree。
既有测试、评分器、验证控制器、运行宿主及 Git 元数据不由作者修改。
编程使用 Codex App Server 持久 thread 和结构化输出；审核使用独立只读会话。
作者和审核分别复用任务运行目录，正文按摘要引用，不递归嵌套历史。

原请求、Case 预期和反馈冻结为目标；机器人未填参考答案时保留原请求，不创建空预期。
输入图片资源与输出图片交付分开。Evaluation 提供受信外部依赖 fixture，真实产品 handler
与消息链继续执行；模拟 OneBot 回执不等于真实 QQ 交付。无法验证的必需项保持缺口。

Codex 原生 developerInstructions 只接收 PromptPlan 的 trusted_policy、trusted_runtime_fact
和宿主执行策略；Bot 指令、动态人格、历史、材料及用户请求仍在 user 输入中。
上下文观测同时记录实际 developer/user 投递，不重复放置宿主正文，也不提升不可信材料。

完整轮次包含作者、对照验证与审核。测试定义返修和审核返修消耗同一轮数，恢复累计预算。
结构化外部阻塞立即停止；连续两轮相同失败阶段及未解决检查、且无新增有效证据时停止。
会话内三次相同动作及结果触发停止，执行状态轮询不作为重复业务动作。
外部执行是否接受不明时保留 ID 并对账，不重复派发。

全部目标与保护集通过且独立审核批准才可 fixed；局部候选为 needs_review，不可自动发布。
取消、失败、预算耗尽保留精确候选与证据，不使迟到结果复活任务。新协议为 pipeline 8，
Code Health 业务保持既有契约。Git 交付仍遵循[交付边界](../../docs/reference/delivery.md)。

## Acceptance

- 改写措辞不能绕过阻塞或无进展停止；不存在无限准备、审核或验证修订循环。
- 基线与候选在独立运行目录执行相同冻结检查，测试变更使旧验证失效。
- 局部候选可读取并明确展示缺口，不能获得完整验收或自动交付资格。
- 任务之间、操作者工作区与受信宿主隔离；沙箱不可用时不启动模型。
- 图片下载、物化、会话发送器、ChannelRuntime、QQ 编码和回执有因果相连的验证。
- 恢复核对任务、会话、源码、环境与凭据身份；取消不提前释放外部执行占用。
- 步骤存储随轮次线性增长，旧任务只读，作者与审核不按轮次创建运行目录。

## Verification

定向回归覆盖有界返修、历史失败回放、局部候选、环境与评分错误、隔离越界、并发取消和恢复。
执行架构、文档及 full 检查，再以明确隔离、禁用发布的试验运行真实模型。
真实模型、隔离协议检查、QQ 外部验收分别报告，不以离线结果替代外部交付证据。
