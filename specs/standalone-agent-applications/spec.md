# 独立应用交付与本机改进

## Summary

AgentStrata 是面向外部应用的 Agent 定制、运行与交付系统。它提供自有基础 Agent 和运行底座，
通过 Harness 根据应用需求，对 Agent 能力及接入组件进行针对性开发与验证，最终交付能够在
目标环境运行的特化 Agent，以及配套的插件、适配器或其他接入组件。不同应用共享基础能力，
保留各自的特化配置与必要实现。

本期将已有运行、Console、Harness、Evaluation 和版本切换能力应用到独立交付副本，
只调整开发仓库依赖、应用版本归属和安装更新入口。首个目标沿用 NapCat/OneBot。
不重做任务图、验收规则、运行链或插件体系；主阶段仍由[主计划](../application-harness-framework/spec.md)维护。

## Design

遵循[四层运行时](../runtime-four-layer-definition/spec.md)和
[六层依赖](../domain-layered-dependencies/spec.md)。公共安装身份与版本解析归 Core；
产物读写与安装归 Deployment；Harness 只将已接受候选交给该入口。
Console 与 Eval 继续使用原控制和执行接口，运行记录仍由 Gateway 采集。

- 首期交付保留现有源码布局、锁文件、配置、检查与部署工具，附带精确内容清单和接受依据。
  接收方无需开发者 checkout；同机按需启用现有 Console、Harness 和 Eval，不强制拆包或拆服务。
- 独立安装显式登记唯一应用、交付来源与安装位置，保留安装自己的 Git 快照以复用 worktree 隔离。
  安装元数据、凭据及业务数据不进入后续候选；宿主生成私有部署路径，不改写交付的应用声明。
- Console、Eval 和 Harness 从所选应用副本工作。受管版本启用后，改进基线使用已启用的精确源码，
  不退回开发仓库或远端 main。首次版本和后续版本均写入执行观测，历史记录不能冒用当前版本。
- 用户从任务详情选择记录并补充目标，复用现有来源冻结、开发、测评、独立确认与审核。
  对话与工具输出是证据，不授予开发权限。应用反馈任务只产生本地候选，不发布 GitHub。
- 安装、准备、启用、查询与撤回沿用现有部署及 M5 控制。开发在隔离副本执行；新版本启用必须
  匹配目标应用当前基线。失败、取消和历史版本漂移保留明确结果，不覆盖会话、记忆或工作区。
- 原仓库工作流和外部插件安装继续按显式来源执行；不把普通目录猜测为独立安装，不增加旧格式回退。

## Acceptance

- 从已验收候选导出的交付物可在无原 checkout、无原任务目录的环境安装，实际 Agent 和配置来源可核对。
- 安装副本可以使用现有 Console 与 Evaluation；未启用开发服务不影响正常业务运行。
- 对话反馈绑定产生记录的应用与版本，在本机隔离开发；不要求 GitHub 凭据或修改远端 main。
- 已验收新版本可准备、启用和撤回；后续任务继续以该版本为基线，其他应用和业务数据不变。
- 篡改产物、跨应用记录、缺失版本、旧版本记录与当前基线不匹配等情况不能取得错误的接受或启用结论。
- 既有来源冻结、权限、验收、版本切换与 Console 行为通过相关回归；真实模型和 QQ 往返单独报告。

## Verification

运行交付安装、应用来源、任务证据、Console/Eval 解析及受管版本的定向测试，再执行项目 full。
用独立目录进行安装与本机反馈闭环验证，明确受控 worker/模型和真实外部链路的区别。
检查文档导航与规格一致性；不为定位调整删除现有运行或验收机制。
