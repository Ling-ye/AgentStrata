# 基于现行契约的逐项代码熵回收

## Summary

代码熵治理逐项发现、修复、验证与交付，批次停止条件与每项尝试分别计量。
现行接口与行为见[代码熵正文](../../docs/reference/code-health.md)。本 accepted 规格保留批次与外部交付的
验收条件，模拟远端回执不能替代真实连续交付验证。

## Design

批次复用 Harness 的运行器、角色、工作区、验收、交付与状态库，不创建第二套发布权限或通用编排器。
每项只冻结一个有源码与规则依据的 finding；受控扩围保留原身份与目标，不能借返工换题。
非确定性推测不能作为自动清理依据。

发现、合并与处理失败分别计数；处理安全收尾后才调查下一项。时间和发现数两种停止条件、等待计时、
未知状态占用、模型预检、定时与公开 API 由[现行批次契约](../../docs/reference/code-health.md)维护。

批次使用[LangGraph](../harness-langgraph/spec.md)，遵循[六层依赖](../domain-layered-dependencies/spec.md)
与[四层运行时](../runtime-four-layer-definition/spec.md)。子任务仍须满足独立验收；全绿基线不证明治理有效。
旧记录与定时配置处理遵循[协议切换](../../docs/reference/harness.md#协议切换)，不改变人工工作区或部署状态。

## Acceptance

- 两种模式均发现一项后完成处理；已合并或处理失败且安全收尾后才发现下一项，不批量攒问题。
- 有效发现、已合并项、处理失败项和每项尝试分别计数，重试与恢复不重复计数、不换题；同题扩围须留存修订证据。
- 时间跨项累计、纯等待不计时；数量模式无隐含时限；预算耗尽不能继续主动复验。
- 无发现提前结束；敏感项和单项失败在安全收尾后继续；无法确认执行或交付状态时批次失败，取消保留证据。
- 并发、回执丢失与重启不重复创建子任务或 PR；同仓库最多一个活动批次。
- 全绿基线允许有证据的治理，业务修复仍保留失败对照；权限和验收边界保持有效。
- Console 提供批次进度和子任务证据；旧字段被拒绝，历史记录不清空。
- 无效模型在创建前被拒绝且不占修复尝试；模型目录查询失败与模型不支持分别报告。

## Verification

使用受控多问题、worker 与 GitHub 回执验证顺序、计数、最新 main、幂等与取消；可控时钟验证
累计预算、恢复和等待。覆盖真实单问题验证流程、API 与 CLI 参数、调度及普通修复回归。
前端执行测试、构建及桌面/窄屏界面检查，随后执行 full。模拟回执不视为真实远端交付证据。
